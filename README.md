# 宝箱をさがせ（佐渡旅代替交流会の謎解きサイト）

佐渡島マップの見た目をコピーして、謎解き用に独立させたサイトです。元の佐渡島マップ（sado_map）とは、コードもデータベースも共有していません。

## できること

- **チームでログイン**：チームを選び、受付で配る4桁の番号を入れる。同じチームなら何台のスマホで開いても同じ画面になる（8秒ごとに自動で更新）。
- **書類**：第一幕から順に書類が届く。正解した書類には「正解」の印がつく。
- **回答（Bot）**：書類の番号を選んで答えを送ると、正解か判定する。正解すると地図にトキの点が2〜3個増える。
- **地図**：60点そろうと点が線でつながり、トキの絵になる。「地点追加」は合言葉が正しいときだけ登録でき、くちばしの先（佐渡金山）の近く（1.5km以内）に登録すると宝箱が見つかる。

## ファイル

| ファイル | 中身 |
| --- | --- |
| `index.html` | 画面とデザイン |
| `app.js` | 画面の動き |
| `api.js` | Supabase とのやりとり（未設定なら試用モード） |
| `config.js` | Supabase の URL と publishable key |
| `p/` | 書類のページ（URLは推測しにくい名前。解いた幕の分だけサーバーが教える） |
| `supabase/setup.sql` | データベースの初期設定（問題・答え・トキの点・チーム） |
| `demo-data.js` | 試用モード用のデータ。本番では使わない |

答え・トキの点の座標・書類ページの名前・チームの番号は Supabase の中にあり、ブラウザから直接は読めません。

## 本番の準備

1. Supabase で謎解き用の新しいプロジェクトを作る。
2. SQL Editor に `supabase/setup.sql` を全文貼り付けて「Run」。チーム名と4桁の番号は、ファイルの下の方で変えられる。
3. `config.js` に Project URL と publishable key を入れる。
4. 本番前に、テストの進み具合を `setup.sql` のいちばん下の「リセット」で消す。

## 運営メモ

- 回答の記録は `nazo_attempts`、正解の記録は `nazo_solves`、登録された地点は `nazo_spots` に入る（Supabase の Table Editor で見られる）。
- 問題の答えを直したら、`setup.sql` を作り直して実行し直す。
